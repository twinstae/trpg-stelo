이 문서는 **D&D 2024 SRD 5.2.1** 영/한 대역의 작업 계획과 규칙입니다. 용어는 [`GLOSSARY.md`](./GLOSSARY.md), 진행 상황은 [목차](/ko/dnd-2024)를 보십시오. 원고 구조와 문체는 앞서 만든 대역(철의 맹세, 던전월드 2, 톨러스)과 같게 맞추고, 용어는 **D&D 5판 베이직 룰 공식 한국어판**을 따릅니다.

## 0. 원고 파일 구조

| 종류 | 위치 | 비고 |
| --- | --- | --- |
| 원천 | [downfallx/dnd-5e-srd-markdown](https://github.com/downfallx/dnd-5e-srd-markdown) | SRD 5.2.1 마크다운 변환본. 스크립트가 커밋을 고정해 `.freebuff/dnd-srd-5.2.1/`에 내려받는다(git에 넣지 않음) |
| 영어 원문 | `src/data/dnd-2024/en/<슬러그>.md` | `bun scripts/dnd-2024-split-srd.mjs`가 자동 생성. 직접 고치지 않음 |
| 한국어 번역 | `src/data/dnd-2024/ko/<슬러그>.md` | **번역은 여기에만** 쓴다. frontmatter 없이 본문만 |
| 단위 목록·상태 | `src/data/dnd-2024/chapters.ts` | 스크립트가 생성. 상태는 한국어 원고 파일의 유무로 정해진다 |
| 대역 렌더 | `src/pages/ko/dnd-2024/[slug].astro` | 절 단위로 좌우 출력 |

원문과 번역은 **헤딩(`##` 이상) 절 단위로 1:1 짝지어** 나란히 렌더됩니다. 그래서 **헤딩의 개수·순서·깊이를 원문과 똑같이 유지해야 합니다.** 어긋나면 스크립트나 빌드가 어느 파일의 몇 번째 헤딩인지 알려 주며 실패합니다. 절 안의 블록(문단·표·인용·목록) 차례까지 같으면 블록마다 줄을 맞춰 보여 주므로, **문단을 합치거나 쪼개지 않는 것**이 읽기에 가장 좋습니다.

번역이 없는 단위는 `status: "pending"`이 되어 사이트가 영어 원문만 보여 줍니다. 그것이 정상 상태입니다.

```bash
bun scripts/dnd-2024-split-srd.mjs            # 영어 원고 재생성 + 한국어 헤딩 구조 검사 + chapters.ts 갱신
bun scripts/dnd-2024-split-srd.mjs --refresh  # 원천부터 다시 내려받기
bun scripts/dnd-2024-split-srd.mjs --check    # 파일을 쓰지 않고 구조만 검사(여럿이 함께 번역할 때)
python3 -I scripts/dnd-2024-boldcheck.py <슬러그>  # 원문에 없는 굵게를 덧붙였는지 검사
bun run build                                 # 대역 짝짓기 검사 + 사이트 빌드
```

### 0.1 스크립트가 원천에 하는 일

* SRD의 13개 파일을 `RANGES`에 적힌 **78개 단위**로 나눕니다. 큰 장(클래스, 주문, 마법 물건, 괴물)은 클래스별·알파벳 구간별로 나눕니다. 각 단위는 대략 한 번에 번역하고 검수할 수 있는 크기(3–50KB)입니다.
* 장 제목(`# …`)은 대역 페이지 머리말이 대신하므로 뺍니다.
* 속성 없는 HTML 표 544개를 마크다운 표로 바꿉니다. `colspan`이 있거나 머리줄이 없는 표 35개는 HTML 그대로 둡니다 — **번역할 때도 HTML 태그를 유지하고 칸 안의 글만 옮깁니다.**
* 모든 헤딩에 영어 슬러그 앵커를 심습니다: `## <a id="the-six-abilities"></a>The Six Abilities`. 한국어 원고에는 **앵커를 옮겨 적지 않습니다.** 앵커가 없으면 대역 페이지가 영어 쪽 앵커를 id로 쓰므로, 한국어 헤딩으로 바꿔도 `/ko/dnd-2024/combat#cover` 같은 링크가 그대로 삽니다.
* 단위 경계를 바꾸려면 원고가 아니라 `RANGES`를 고치고 스크립트를 다시 돌립니다.

## 1. 작업 계획

### 1.1 순서

용어를 먼저 굳히고, 그 용어를 많이 쓰는 덩어리를 뒤에 옮깁니다.

| 단계 | 단위 | 규모 | 목표 |
| --- | --- | --- | --- |
| 0 | 인프라·용어집 초안·샘플(`rhythm-of-play`) | 1단위 | 파이프라인 확인, 문체 견본 확정 |
| 1 | **게임 플레이** 나머지 7단위 | ~60KB | 2024년 신규 용어(d20 판정, 영향력 행사·연구·사용 행동…) 확정 |
| 2 | **규칙 용어집** 5단위 | ~70KB | 용어집을 실제 번역으로 굳힘. 이후 단계는 이 표기를 기준으로 삼음 |
| 3 | **캐릭터 만들기**, **캐릭터 기원**, **재주** 6단위 | ~60KB | 플레이어가 캐릭터를 만들 수 있는 최소 세트 |
| 4 | **장비** 6단위 | ~65KB | 무기 속성·숙달, 도구, 모험 장비 |
| 5 | **클래스** 12단위 | ~240KB | 한 클래스씩. 클래스 요소 이름을 용어집에 추가하며 진행 |
| 6 | **주문** 10단위 | ~320KB | 먼저 **주문 이름 표**(영→한)를 베이직 룰 한국어판에서 옮겨 와 용어집에 만들고 나서 본문 |
| 7 | **게임 진행 도구** 7단위 | ~50KB | GM용 규칙 |
| 8 | **마법 물건** 8단위 | ~225KB | 먼저 물건 이름 표(베이직에 있는 것은 그 표기로) |
| 9 | **괴물**, **동물** 16단위 | ~520KB | 먼저 괴물 이름 표(베이직에 있는 것은 그 표기로)와 자료 상자 견본 한 개를 확정한 뒤 반복 |

1–4단계(약 255KB)를 마치면 “기본 규칙만으로 한 판 해 볼 수 있는” 상태가 됩니다. 5단계 이후는 분량이 크지만 형식이 반복되므로, 단계 첫 단위에서 견본을 확정하고 나머지는 같은 틀로 옮깁니다.

### 1.2 단위 하나의 작업 흐름

1. `GLOSSARY.md`의 관련 절을 훑습니다. 이미 번역한 단위와 표기가 다르면 용어집이 우선입니다.
2. `src/data/dnd-2024/en/<슬러그>.md`를 복사해 `ko/<슬러그>.md`를 만들고, **앵커를 지운 뒤** 위에서부터 옮깁니다.
3. `bun scripts/dnd-2024-split-srd.mjs`로 헤딩 구조를 검사합니다. 상태가 `translated`로 바뀝니다.
4. `bun run dev`로 대역 페이지를 열어 표·인용·목록이 양쪽에서 나란히 맞는지 봅니다.
5. 새로 지은 용어를 `GLOSSARY.md`에 추가합니다.
6. 커밋: `feat: D&D 2024 SRD <단위 한국어 제목>` (용어 통일 수정은 `fix: …`).

### 1.3 검수

* 단계가 끝날 때마다 그 단계 단위들을 이어 읽으며 용어·어미를 한 번 더 맞춥니다.
* 2단계(규칙 용어집)를 마치면 1단계 단위를 용어집에 맞춰 다시 훑습니다.
* 용어집의 `근거` 칸이 `추정`인 말은 더 큰 공식 자료(플레이어즈 핸드북 한국어판 등)를 구하면 먼저 대조하고 원고를 일괄 치환합니다.

## 2. 문체

| 항목 | 규칙 | 예 |
| --- | --- | --- |
| 종결 | **“~합니다 / ~하십시오”** (다른 대역과 같게) | “d20을 굴리고 수정치를 더합니다.” |
| 규칙 동사 | 굴립니다, 더합니다, 뺍니다, 받습니다, 잃습니다, 회복합니다, 고릅니다 | |
| 2인칭 | 단수 **당신**, 플레이어 집단 **여러분** | “당신의 캐릭터는 …” (베이직과 같음) |
| 캐릭터 | 성별을 특정하지 않음. 원문의 they/it도 “그 크리쳐”, “목표”처럼 명사로 받거나 문장을 비틀어 씀 | |
| GM 안내 | **“~할 수 있습니다 / ~하십시오”** | |
| 강조 | 원문의 굵게·기울임을 **그대로** 살림. **원문에 없는 굵게를 용어에 덧붙이지 않음** | 원문 `These rolls are called D20 Tests` → “d20 판정(D20 Test)이라 하며” (굵게 없음) |

* 문장은 짧게 끊고, 수동태와 “~하는 것이 가능합니다” 같은 번역투를 피합니다.
* 원문은 규칙 용어를 대문자로 씁니다(`Hit Points`, `the Prone condition`, `Bonus Action`). 한국어에는 대문자가 없으니 **용어집 표기를 일관되게 쓰는 것**으로 대신하고, 따로 꾸미지 않습니다.
* 굵게 끝난 말 뒤에 조사가 바로 붙으면 **한 칸 띄웁니다**: `**이점** 을 받습니다`. 괄호·쌍점은 붙입니다: `**숙련 보너스(Proficiency Bonus)**`, `**명중:**`.

## 3. 형식별 규칙

### 3.1 헤딩

* 한국어만 씁니다. 왼쪽 칸에 영어가 있으므로 헤딩에 영어를 병기하지 않습니다.
* 용어집 항목의 꼬리표는 옮깁니다: `#### Grappled [Condition]` → `#### 붙잡힘 [상태]`.
* 번호 붙은 굵은 머리(`**1: The Game Master Describes a Scene.**`)는 번호와 마침표를 그대로 둡니다: `**1: GM이 장면을 묘사합니다.**`

### 3.1.1 상호 참조

원문의 `"Playing the Game"`, `see "Rules Glossary"` 같은 장·절 참조는 **「」**로 옮깁니다: `「게임 플레이」`, `「규칙 용어집」을 보십시오`. `later in "Playing the Game"` → `「게임 플레이」 뒤쪽`. 큰따옴표(" ")는 원문이 실제 대사나 이름(“natural 20”)을 인용할 때만 씁니다.

### 3.1.2 조사와 줄바꿈

* 영어를 병기한 말 뒤의 조사는 **한국어 말에 맞춥니다**: `목표(Target)는`, `정신감응(Telepathy)은`.
* 원문 문단 안의 잘못된 줄바꿈은 그대로 따라 두어도 되고 합쳐도 됩니다(화면에서는 같은 문단). 줄 끝의 `<br>`은 반드시 따라 씁니다.

### 3.2 표

* 표 제목(표 위의 `**Ability Scores**` 줄)도 옮깁니다.
* 머리줄과 칸 수를 바꾸지 않습니다. 숫자·주사위·기호(—, −, +)는 그대로 둡니다.
* HTML로 남은 표는 태그와 속성(`colspan` 등)을 건드리지 않고 칸 안의 글만 옮깁니다.

### 3.3 인용 상자

원문의 곁글은 `> **EXCEPTIONS SUPERSEDE GENERAL RULES**`처럼 대문자 제목을 단 인용입니다. 제목은 굵게 한국어로 옮기고(베이직에 같은 곁글이 있으면 그 제목을 씀: `ROUND DOWN` → **나머지 버림**)(대문자 흉내는 내지 않음), 인용 표시(`>`)와 빈 인용 줄(`>`)을 원문대로 둡니다.

### 3.4 괴물·주문·마법 물건 상자

* 기울임 머리줄: `_Large Aberration, Lawful Evil_` → `_대형 기괴체, 질서 악_`, `_Level 1 Enchantment (Bard, Cleric, Warlock)_` → `_1레벨 환혹술 (바드, 클레릭, 워락)_`.
* `**AC** 17 **Initiative** +7 (17) <br>` 같은 줄은 `<br>`, `&emsp;`, `<hr>`를 그대로 둡니다.
* 능력 이름 줄 `**_Tentacle._** _Melee Attack Roll:_ +9, reach 15 ft. _Hit:_ …`은 굵은기울임·기울임 모양을 유지합니다: `**_촉수._** _근접 명중 굴림:_ +9, 간격 15ft. _명중시:_ …`
* 주문·물건·괴물 이름은 해당 단계 시작 전에 이름 표를 만들어 용어집에 올리고 그대로 씁니다.
* 사이트는 이 항목들을 카드로 묶어 보여 줍니다(`src/utils/dndEntries.ts`, `src/styles/dnd.css`). 자료 상자는 헤딩 깊이와 영어 앵커(`traits`, `actions` …)로 알아보므로, 헤딩 깊이를 원문과 똑같이 지키면 번역 쪽도 같은 모양이 됩니다.

## 4. 용어 병기 규칙

1. **공식 용어**(예: **숙련 보너스**, **d20 판정**)는 **파일당 첫 등장 한 번**만 `(영어)`를 붙입니다. 이후에는 한국어만.
2. 용어집에 이미 있는 말은 용어집 표기를 그대로 씁니다. 베이직 룰 한국어판에 익숙한 플레이어가 바로 알아볼 수 있는 것이 최우선입니다. 다른 대역(톨러스의 “피트”, “전사” 등)과 달라도 이 대역은 용어집을 따릅니다.
3. 2024년 규칙에서 새로 생긴 말은 베이직 어투로 지어 용어집에 `신규`로 올리고, 같은 커밋에서 기존 원고를 grep해 통일합니다.
4. `fiction`, `narrative` 같은 말은 이 책에서 드뭅니다. 나오면 다른 대역처럼 **이야기 속 현실**, **이야기**로 옮깁니다.

## 5. 하지 말 것

* 헤딩을 새로 만들거나 합치거나 빼기(대역 짝짓기가 깨집니다).
* 한국어 원고에 앵커(`<a id>`)나 frontmatter 넣기.
* 원문에 없는 규칙 설명 덧붙이기, 5판 규칙과 다른 점을 역주로 달기.
* 용어를 임의로 바꾸기(예: **내성 굴림** → “세이빙 스로”, **명중 굴림** → “공격 굴림”, **크리쳐** → “생물”, **30ft** → “30피트”).
* 숫자·주사위 식·기호 고치기(원문의 오류처럼 보여도 그대로 두고 따로 기록합니다).
